# 다른 프로젝트에도 재사용할 공통 시스템 후보

2026-10-02 · 사용자 의도 정정: 이 게임 안의 공통화가 아니라 다른 프로젝트로 가져갈 시스템을 기록한다.


| 후보 | 재사용할 책임 | 이 프로젝트에 남길 것 | 추출 시점 |
|---|---|---|---|
| UI 화면·팝업 | 화면 전환, 팝업 스택, 뒤로가기, 입력 차단, 안전 영역 | 작품·상점·관람객 화면과 미술관 스타일 | 두 번째 프로젝트에서 동일 흐름을 사용할 때 |
| 오디오 | BGM·효과음 재생, AudioMixer 채널, 음량·음소거, 재생 수명 | 붓질·관람객·보상 음원 및 재생 조건 | 첫 오디오 구현 시 재사용 가능한 경계를 정하고, 다른 프로젝트에서 검증 후 추출 |
| 저장 | 파일 원자 저장, 백업 복구, 버전 마이그레이션 | SaveData의 작품·전시·성장 규칙과 검증 | 새 프로젝트에서 저장 포맷이 확정될 때 |
| 설정 | 음량·언어·접근성 설정 저장 및 적용 | 게임별 설정 항목과 화면 디자인 | 설정 화면 도입 시 |
| 알림·연출 | 토스트 수명, 대기열, 숫자 증가·페이드 | 코인·미술관 확장 문구와 지급 조건 | 다른 프로젝트에서도 같은 알림이 필요할 때 |
| 입력·제스처 | UI 입력 분리, 확대·이동, 터치 좌표 변환 | 픽셀 칠하기·색상·붓 규칙 | 두 번째 캔버스/지도 도구에서 공통 요구가 확인될 때 |

## 운영 원칙

- 작업 중 재사용 후보를 발견하면 이 문서에 책임·게임 의존성·추출 시점을 추가한다.
- 후보 기록과 공용 패키지 제작은 구분한다. 현재는 후보만 기록하며, 다른 프로젝트에서 확인하기 전에 범용 프레임워크를 만들지 않는다.
- 미술관 경제·관람객 취향·그림 분석·전시 배치는 게임 고유 기능이다. 공통 시스템으로 분류하지 않는다.
- 추출하게 되면 게임별 코드가 공통 시스템을 호출하도록 경계를 잡고, 공통 시스템이 GallerySession이나 Artwork를 직접 참조하지 않게 한다.

## 추가 후보 · 선택형 성장 노드

다른 프로젝트에서도 사용할 수 있는 부분은 노드 연결·선행 조건 표시, 선택/잠김/완료 상태, 상세 패널 및 구매 요청 흐름이다. 효과 계산과 비용·해금 규칙은 게임별 구현에 남긴다. 현재는 조사안만 있으며, 별도 공용 패키지는 만들지 않았다. 조사: Docs/skill-node-growth-proposal.md.
